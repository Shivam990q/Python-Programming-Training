⚠️ Truncation Invariant: Shortest Iterable Dictates Length

Python's zip() stops silently when the shortest iterable is exhausted! Extra items are discarded. In Python 3.10+, use zip(..., strict=True) to raise a ValueError if lengths differ, or itertools.zip_longest(..., fillvalue=None) to preserve all items.

🔄 Matrix Transposition via zip(*matrix) Idiom

How does *matrix work? The star unpacks 3 rows as 3 separate arguments to zip: zip(row1, row2, row3). Zip pairs up elements at index 0, index 1, index 2 — effectively turning rows into columns!

Placement Trap: Lazy Iterators in Python 3

In Python 3, zip() returns an iterator object (<zip object at 0x...>), not a list! If you print it directly, you won't see elements. Furthermore, iterators are single-pass: once looped over, it becomes empty!

sorted() vs list.sort() Fatal Mistake

sorted(iterable) returns a brand new list and works on any iterable (strings, tuples, dicts). In contrast, list.sort() sorts in-place and returns None! Writing x = lst.sort() sets x = None!

🔥 The Notorious '\r' Carriage Return Trap

In ASCII, \r (Carriage Return, 0x0D) moves the cursor back to the beginning of the current line without creating a new line. Subsequent characters overwrite whatever was printed before!

print("Loading...\rDone!")
# Output: 'Done!ng...' ('Done!' overwrote 'Load')

Live Progress Bars in Console

This exact carriage return behavior is how CLI download bars like tqdm work! They repeatedly output print(f"\rDownloading: {pct}%", end="") so the user sees a single animated line instead of thousands of newlines.

⚠️ The #1 Raw String Placement Trap: Trailing Backslash SyntaxError

Can a raw string end in an odd number of backslashes? NO!

r"C:\Users\" → SyntaxError: unterminated string literal

Why? Even in raw strings, the tokenizer looks for \" to allow escaped quotes! The final backslash escapes the closing quote, leaving the string unclosed. Correct pattern: r"C:\Users" + "\\" or os.path.join() / pathlib.Path.
